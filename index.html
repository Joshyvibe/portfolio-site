Section:: 01 / About

20+ products in production. Most of them you'll never see named here.

I'm a full-stack engineer who takes products from idea to store listing — web, mobile, AI and automation — with five years of extra depth in the part most people avoid: authorization boundaries, payment state reconciliation, and the request path where a shortcut today becomes an incident later. I started in international money transfer at a commercial bank — onboarding partner APIs into core banking and resolving settlement disputes nationwide — which is where "the money moved, but did it actually reconcile?" became a permanent instinct rather than a checklist item.

Since then I've shipped 20+ projects to production. Most were built for clients under NDA, so they don't appear here by name — but I'm happy to walk through the architecture and the trade-offs behind that work in conversation, without naming the client.

The work I can show publicly starts with EstatePadi, a multi-tenant estate-management platform I've architected and built solo since late 2022 — residents, estate admins, and gate security on one Django/DRF codebase, taken from data model to a published Android app — and Anwrk, an artisan marketplace live on the web.

Every one ships with the test that would fail if the hard claim were false, and the code is there to read.

Section:: 04 / How I work

Four rules I keep re-deriving on every project.

01

Authorization lives in the request path.

Not the interface, not a flag trusted at read time. If the client has to be honest for the boundary to hold, the boundary doesn't hold.

02

Prove it, don't assert it.

"No oversell," "no duplicate charge," "no cross-tenant leak" are all claims. Each one gets a test — real concurrency, real replay, real crash — that would fail if the claim were false.

03

Idempotency isn't an edge case.

Webhooks get redelivered. Workers get killed mid-job. Connections drop mid-write. Design for that on the first pass, not as a hotfix after the first incident.

04

Boring infra, hard problems.

Postgres, Redis, well-understood tools I trust — then spend the complexity budget that saves on the part of the system that's actually novel.
